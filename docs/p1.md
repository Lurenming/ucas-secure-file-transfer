## 3. 数据与账户创建

默认路径为 `server-node/data/accounts.sqlite`，WAL/SHM 文件位于同一目录。Windows 创建专用目录时移除继承权限并授予当前运行用户目录及子项完全控制；POSIX 使用目录 0700、数据库 0600。失败则报错，不回退到公共存储。使用同一 Windows 用户运行创建命令和后端。

`SFT_DATA_DIR` 可指定另一个**专用数据目录**，启动时会收紧该目录权限，不应指向共享资料目录。默认项目根和盘符根路径被拒绝。测试总是传入其自己创建的临时目录，删除前核对绝对路径及前缀；从不清空开发数据库。`.gitignore` 覆盖 `data/`、`*.sqlite`、`*.sqlite-*`、`*.db`、`*.db-*`，包括 WAL/SHM/日志型数据库伴随文件。

`users` 是 STRICT 表：

| 字段 | 类型及作用 |
| --- | --- |
| `user_id` | TEXT 主键，服务器创建 UUID |
| `username` | TEXT，NOT NULL，UNIQUE COLLATE BINARY；保存规范化后的名字 |
| `password_hash` | BLOB，64 字节派生结果 |
| `salt` | BLOB，每账户独立随机 16 字节 |
| `algorithm` | TEXT，固定 `scrypt` |
| `n`, `r`, `p` | INTEGER，保存计算参数 |
| `key_length`, `maxmem` | INTEGER，保存长度与计算内存限制 |
| `created_at` | TEXT，UTC ISO 时间 |

除主键外上述字段均为 NOT NULL。用户名必须匹配 `^[A-Za-z][A-Za-z0-9_]{2,31}$`：3–32 个 ASCII 字母、数字或下划线，以字母开头；转小写后存储，因此 Alice/ALICE/alice 是同一账户。不 trim，不接受全角或其他 Unicode 用户名。数据库唯一约束最终防止并发重复写入，重复创建明确失败，不更新旧密码。

查询使用 `WHERE username = ?`，插入也全部使用 `?` 参数绑定；没有拼接用户输入的 SQL。校验用户名是第一层输入限制，参数绑定是独立的数据库保护。

```powershell
Set-Location 'D:\UCAS\软件与系统安全\lab1\server-node'
npm.cmd run user:create -- alice
# 在终端中输入密码并再次确认；两次都不回显。
```

命令只接受用户名参数，要求交互 TTY；拒绝通过参数或管道提交密码。密码不进入命令历史、日志或源码，Ctrl+C 可取消。过长输入、确认不一致、重复用户名都明确失败。不要把密码写在命令后面。

## 4. 密码方案与计算边界

- 密码至少 12 个 Unicode 码点，最多 256 个 UTF-8 字节，拒绝无效 UTF-16；不 trim、不规范化、不静默截断。空格作为密码本身的一部分保留。
- 固定参数：`N=131072, r=8, p=1, keyLength=64, maxmem=201326592`（192 MiB）。每账户 `randomBytes(16)` 产生盐。
- `promisify(crypto.scrypt)` 让耗时派生在 libuv 工作线程执行；`timingSafeEqual` 比较等长派生结果。不存在的用户名也执行同参数 scrypt 和等长比较，对外统一 `AUTH_FAILED / 用户名或密码错误`。数据库记录的算法/参数异常时同样走假记录校验，不能用记录降低或无限提高成本。
- 单次派生理论工作内存约 128 MiB，加实现开销；最多两次认证派生并行。192 MiB 是每次允许上限，不等于恒定实际占用。实测单次约 324–335 毫秒，最后一次为 331.2、323.6 毫秒，仅代表本机。
- 可清除的输入/派生字节缓冲在 finally 中清零；C# 发送完立即清零序列化缓冲，不在待响应表保存密码。JavaScript/C# 的不可变字符串不能保证物理内存立即擦除，因此不宣称内存取证层面的零残留。不会持久化明文密码或记录原始认证消息。

参数和实现依据：[Node crypto.scrypt](https://nodejs.org/download/release/v22.16.0/docs/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback)、[OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

## 5. 协议与状态

继续使用 UTF-8 JSON 文本、`version:1`、UUID `requestId`、对象 `data`。每次请求一个新 requestId。所有响应含本连接 connectionId；HELLO 和 ECHO 保留。密码只出现在加密 WSS 的 AUTH_LOGIN 请求体，地址中不允许用户信息、查询参数或片段。

| 请求 type | data | 成功响应 type / data |
| --- | --- | --- |
| `AUTH_LOGIN` | `username` 字符串、`password` 字符串，按上面的长度/格式校验 | `AUTH_LOGIN_RESULT`；`userId`, `username`, `expiresAt` |
| `AUTH_ME` | `{}` | `AUTH_ME_RESULT`；当前绑定的 `userId`, `username`, `expiresAt` |
| `AUTH_LOGOUT` | `{}` | `AUTH_LOGOUT_RESULT`；`{}` |
| `ECHO` | `text`，最多 1024 个 UTF-16 代码单元 | `ECHO_RESULT`；原文本 |

登录/ME 响应只含公开身份字段和 UTC 过期时间，不含密码、盐、哈希或算法参数。AUTH_ME 即使额外提交 userId，也不会使用它：身份只能取服务器本连接的绑定。未知字段不作为授权依据。

统一认证错误格式：

```json
{"version":1,"type":"ERROR","requestId":"对应请求的 UUID","connectionId":"本连接 UUID","code":"AUTH_FAILED","message":"用户名或密码错误"}
```

| code | 含义 |
| --- | --- |
| `AUTH_REQUIRED` | 未登录或身份已经过期 |
| `AUTH_FAILED` | 合法格式的用户名/密码校验失败；不区分不存在用户和密码错误 |
| `AUTH_ALREADY_LOGGED_IN` | 已登录，必须先注销才能切换账户 |
| `AUTH_BUSY` | 同一连接已有一次登录计算进行中 |
| `AUTH_RATE_LIMITED` | 失败退避、连接或全局尝试预算不足 |
| `AUTH_SERVER_BUSY` | 计算队列已满或排队超时 |
| `AUTH_CANCELLED` | 登录期间注销、连接关闭或代次已变化，旧结果失效 |
| `INVALID_MESSAGE` | 版本、类型、requestId、data 或凭据格式不合法 |
| `INTERNAL_ERROR` | 内部操作失败，响应不包含异常细节 |

非法 JSON 仍返回 `INVALID_JSON`，无法识别合法 requestId 时不回显它。错误不向进程顶层抛出。

| 事件 | 服务器状态与连接行为 |
| --- | --- |
| 连接成功、HELLO | 已连接未登录；启动 120 秒认证等待期限 |
| 登录成功 | userId 绑定当前连接，绝对有效期 15 分钟；停止认证等待计时 |
| AUTH_ME / ECHO / PING/PONG | 不延长绝对会话有效期，也不延长未认证等待期 |
| 已登录后注销 | 清除身份、保留 WSS，重新开始 120 秒等待 |
| 未登录时重复注销 | 返回成功，但不能刷新等待期限 |
| 会话过期 | 清除身份，主动发送 `AUTH_EXPIRED`、`data:{}`（无 requestId），同连接可再次登录；开始新等待期 |
| 未认证等待超时 | 关闭码 1008，清理状态；失败登录不能无限续期 |
| 断开、服务停止 | 清除身份和定时器；重连必须再次登录，无自动身份恢复 |

ECHO 是受消息/连接限制的诊断功能，允许未登录使用，但成功不代表认证成功。未认证连接已不再允许无限空闲；P0.2 的真实 61 秒保活测试仍保留，61 秒小于生产等待期限 120 秒。

## 6. 并发、防旧回调与限额

| 限制 | 正式配置 |
| --- | --- |
| 每连接同时登录 | 1 次 |
| 全局同时 scrypt | 2 次 |
| 全局等待队列 | 最多 4 个，等待最多 3 秒 |
| 每连接尝试预算 | 初始/最大 5 个令牌，每 12 秒补 1 个 |
| 全局尝试预算 | 初始/最大 20 个令牌，每 3 秒补 1 个；重连不会重置 |
| 同连接失败退避 | 连续失败后等待 1、2、4、8 秒，之后上限 8 秒 |
| WSS / TCP 连接 | 最多 32 / 64 |
| 消息 / 单连接发送队列 | 16 KiB / 64 KiB |
| 保活 | 协议 PING 每 15 秒，匹配 PONG 等待 10 秒；压缩关闭 |
| 服务关闭等待 | 5 秒后清理残留 socket |
| C# 待响应请求 | 最多 8 个，请求超时 10 秒，发送串行化 |

先验证和限速，再读账户、提交昂贵计算。只保存一个全局令牌桶和每个已连接客户端的固定状态，无按用户名/IP 无限增长的映射。连接关闭时释放状态，等待任务取消时立即移出有限队列。已开始的原生 scrypt 不能强制中断，但最多两份，完成后丢弃失效结果、清零缓冲；不会恢复注销/断开后的身份。

每次登录/注销/失效改变“代次编号”。异步计算开始时保存编号，结束时还要检查代次、取消状态、连接仍 OPEN 和认证截止时间，全部匹配才可绑定身份。服务停止先禁止新任务、取消队列、使所有身份失效，再关闭 WSS 和 HTTPS。

C# 同样用认证代次保护回复，在接收循环中更新身份后才完成请求任务；迟到登录/ME 不能覆盖注销后的状态。注销结果不确定或登录被取消时关闭连接，避免界面与服务器保留不同的可用身份。IdentityChanged 和本地过期计时器驱动窗体状态，窗体仍使用连接对象和窗口代次过滤旧回调。

对初学者而言，`await scrypt(...)` 表示“等待这个密码计算完成再继续此请求”，并不会让整个 Node 服务等待；限制并发避免它耗尽机器资源。参数绑定将 SQL 模板与数据分开，输入中的引号不会改变查询结构。连接内身份是服务器保存的状态，不是客户端说自己是谁就相信谁。代次编号相当于任务的有效版本：注销后旧版本任务即使算完，也没有权限写回身份。
