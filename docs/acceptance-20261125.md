## 模拟磁盘空间不足的具体边界

服务端分别模拟：已ACK8192字节后仅写入下一块117字节便报ENOSPC、刷盘失败、刷盘后SQLite检查点提交失败、最终预提交失败、创建独占最终链接后的SQL提交失败。前三项服务器仍只认可8192字节；后两项已可靠接收完整65539字节，但失败状态未向文件列表发布完整对象。重新认证/恢复走现有可信检查点机制，完整大小和SHA-256一致；同一轮另一个账户的任务继续完成。

客户端模拟：下载部分写入后磁盘满、刷盘失败、JSON检查点提交失败，以及首次入队记录保存失败。下载失败后目标不发布，任务退出“传输中”，句柄可被独占重新打开；从持久化8192字节前缀恢复并安全处理未确认尾部。首次入队保存失败可以在故障解除后重试同一个任务ID。已有目标哨兵未被覆盖。套件结束活动任务与WSS连接均为0。

所有“磁盘满”均为**模拟磁盘空间不足测试**。服务端只包装夹具实例的写入/检查点/SQL方法；C#故障钩子仅在ConnectionChecks定义SFT_TEST_IO时编译，交付GUI不编译这些故障开关。没有填满任何真实磁盘。早期建立独立VHD的尝试受权限限制，未挂载、未格式化；最新范围不再依赖此条件。

## 发现、修复和必要复测

1. 新增测试初次编译出现CS4007（ReadOnlySpan跨await）；改为先读取数组再比对。失败回执 artifacts/validation/2026-11-24T16-27-51-373Z-build 保留；最终完整构建通过。
2. 真实GUI中有4次修复前上传尝试因“Access to the path is denied”进入待恢复。捕获实际EXE堆栈确认发生在TransferState.Save的File.Move检查点替换，未关闭TLS、取消配额或绕过ACL。原始占用进程未确定；用真实文件句柄占用复现了同类Windows替换失败。
3. TransferState.SaveAsync仅对已刷盘JSON替换的Windows错误5/32/33做最多6次尝试，延迟10/25/50/100/200毫秒，异步累计最多385毫秒。持续拒绝仍明确失败，不将其计为成功，不重试磁盘空间不足错误。旧持久记录保留。最终真实GUI再次捕获一次短暂拒绝，被重试处理，任务没有失败。
4. TransferQueue.Enqueue首次保存失败曾可能留下未入队的登记；现在撤销登记并显示待恢复。新增模拟磁盘满用例验证同一任务随后可重新入队、上传完成。
5. 修改后执行完整后端43/43、完整.NET构建、23条C#/Node增强联调、9个模拟故障场景、真实文件占用测试、8条窗体回归，并复做受影响的GUI并发/下载暂停/取消/注销/关窗恢复。没有跳过失败测试。

修复前两项上传已恢复完成，另两项诊断上传保留在本轮密码/mTLS隔离目录，各一项，受24小时保留期及128MiB配额约束。这不是最终GUI批次的遗留任务，也不应将这些历史尝试全部计为成功。

## 可用于报告的两段文字

**实现概述：** 本系统采用C# WinForms客户端、Node.js服务端和SQLite，通过严格验证证书的HTTPS/WSS连接进行安全文件传输。客户端使用独立控制连接及有界传输连接池，服务端按认证账户检查文件归属、登记mTLS证书并聚合控制上下行带宽。上传依赖服务器持久检查点，下载通过私有临时文件和恢复记录续传，最终验证完整大小与SHA-256。验收修订加强了本地检查点短暂占用时的有界异步重试，以及首次任务记录保存失败时的队列清理。

**实验结论：** 在隔离环境中，最终源码通过43项后端回归、完整.NET构建、真实C#/Node增强联调、9个模拟磁盘空间不足场景及Windows文件占用回归。真实桌面操作验证了同窗口两上传加两下载、暂停恢复、单项取消、注销、正常关窗后的恢复、不可写目录处理及PFX证书登录；最终并发批次3项完成、1项主动取消，完成文件的大小与SHA-256一致。上述结果属于本机功能验证，不代表真实双机通信、正式专用账户部署、长期压力或真实断电测试通过。
