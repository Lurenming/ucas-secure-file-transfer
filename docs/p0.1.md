## 5. 如何启动、检查和停止

在第一个 PowerShell 窗口执行：

```powershell
Set-Location 'D:\UCAS\软件与系统安全\lab1\server-node'
npm.cmd start
```

依赖已经安装，现在可以直接启动。以后在缺少依赖的新副本中，可先执行 `npm.cmd ci`，按锁文件安装，再启动。此次没有另外执行 `npm.cmd ci`。

这里使用 `npm.cmd` 明确调用 Windows 的命令脚本，可避免 PowerShell 选择 `npm.ps1` 时遇到脚本执行策略问题；它运行的仍然是 `package.json` 中的 `start` 命令。

成功启动后，终端显示：

```text
[server] Listening on http://127.0.0.1:3000 (P0.1, HTTP, local only)
```

在第二个 PowerShell 窗口检查：

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:3000/health' | ConvertTo-Json
curl.exe -i http://127.0.0.1:3000/health
curl.exe -i http://127.0.0.1:3000/not-defined
```

`GET /health` 返回 HTTP 200，`Content-Type` 为 JSON，正文为：

```json
{
  "status": "ok",
  "service": "SecureFileTransfer.Server",
  "stage": "P0.1"
}
```

未定义的路径返回 HTTP 404 和 `{"error":"Not Found"}`。不要只检查正文，使用 `curl.exe -i` 还可以查看状态码和响应头。

回到启动服务的窗口，按 **Ctrl+C**。正常停止日志：

```text
[server] Received SIGINT; stopping...
[server] Stopped; listening port released.
```

Windows 的 npm 批处理包装层可能继续询问“终止批处理操作吗 (Y/N)?”，输入 `Y` 并回车即可结束包装层。

停止后检查监听端口：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 3000 -ErrorAction SilentlyContinue
```

没有输出表示没有查到该端口的监听记录。此时再次请求 `/health` 应连接失败；重新执行 `npm.cmd start` 可以再次启动。验收时还实际重新绑定了 `127.0.0.1:3000`，确认操作系统允许复用端口，然后关闭了检查用的监听器。

如果启动时端口已被占用，会看到：

```text
[server] Cannot listen on http://127.0.0.1:3000: port 3000 is already in use (EADDRINUSE). No other process was stopped.
```

本次启动以退出码 `1` 结束；不会结束占用端口的程序，也不会自动换端口或改成对外监听。

## 6. 关键代码解释

### package.json

- `"type": "module"`：让本工程的 `.js` 文件使用 `import` 和 `export`。
- `"start": "node src/server.js"`：执行 `npm.cmd start` 时，npm 实际运行这一条命令。
- `"private": true`：防止误将课程后端发布为 npm 包。
- `engines.node`：声明工程使用 Node 22 或更高版本；不会自动安装或升级 Node。

### src/app.js：请求进来之后做什么

`express()` 创建一个应用对象。`app.get('/health', ...)` 注册一个 GET 路由：路径匹配时执行后面的函数。函数中的 `_req` 是请求对象，本接口没有使用它；`res` 是响应对象。`res.json(...)` 把 JavaScript 对象转换为 JSON 并发送给调用者。

路由后面的 `app.use(...)` 是兜底处理：前面没有响应的请求会到达这里，得到 404。顺序很重要，如果把它放在健康检查路由前面，健康检查也会被它提前处理。

`export default app` 把应用交给其他文件使用。这个文件没有调用监听方法，所以单独导入它不会占用端口，后续可以方便地独立测试路由。

### src/server.js：服务在哪里运行、如何退出

`createServer(app)` 使用 Node 自带的 HTTP 模块创建服务器，并让 Express 处理收到的请求；不需要额外安装 HTTP 包。`import app from './app.js'` 中保留 `.js` 扩展名，符合这里的 ESM 文件导入方式。

`server.listen(port, host, ...)` 请求监听本机回环地址。当前地址固定为 `127.0.0.1`，端口固定为 `3000`，未增加环境变量覆盖。监听成功后的回调通过 `server.address()` 获取实际地址再打印，避免在监听失败时误报启动成功。

`server.on('error', ...)` 处理服务器错误。`EADDRINUSE` 表示地址/端口已占用，代码打印明确原因，并用 `process.exitCode = 1` 标记本次运行失败；没有杀进程或重新分配端口的操作。

Ctrl+C 通常触发 `SIGINT`。对应回调调用 `server.close()`，停止接收新连接并等待已有请求结束。`stopping` 防止重复执行关闭逻辑。如果已有连接一直不结束，5 秒后 `closeAllConnections()` 会关闭本服务器剩余的 HTTP 连接；`unref()` 使这个定时器本身不会拖住已经可以退出的进程。关闭完成后清除定时器并打印日志。

代码也注册了 `SIGTERM` 处理，但没有在本次 Windows 验证中单独测试此分支。这里的连接关闭逻辑服务于 P0.1 HTTP；下一阶段加入 WebSocket 时，还需要另行管理升级后的 WebSocket 连接。

参考：[Express 5 官方 API](https://expressjs.com/en/5x/api/)、[Node v22.16.0 HTTP 关闭接口](https://nodejs.org/download/release/v22.16.0/docs/api/http.html#serverclosecallback)、[Node v22.16.0 信号事件](https://nodejs.org/download/release/v22.16.0/docs/api/process.html#signal-events)。
