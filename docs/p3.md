## 2. 文件列表和授权

只读现有 `files` 表中 `owner_id = 当前服务器身份.userId AND state = 'committed'` 的行。所有带输入的 SQL 均为 prepared statement 参数绑定。增加索引 `(owner_id, state, committed_at DESC, file_id DESC)`；原表、数据和提交恢复流程保持兼容。文件路径始终由可信存储目录和服务器生成的 fileId 推导，客户端不能传路径或改变 owner。

`FILES_LIST {limit?, cursor?}` 返回 `FILES_LIST_RESULT {files, nextCursor}`。files 每项仅有 `fileId, name, size, sha256, committedAt`；不返回 owner、connectionId 元数据字段或真实文件路径。协议外层的 connectionId 仍是当前 WSS 的 ID。

- 默认 10 条，最多 20 条，每次 SQL 最多取 21 行，额外一行仅判断是否还有下一页。
- 按 `committed_at DESC, file_id DESC` 排序，采用键集分页；下一页只取排序键严格小于游标的行，避免用无界 offset 扫描。
- 游标为 `base64url({at,id}) + '.' + base64url(HMAC-SHA256)`，签名绑定当前 userId；不保存用户游标表。字符串最大 256 字符，校验格式、签名、ISO 时间及 UUID。
- 游标不是凭证，也不是下载授权。其他用户的游标、篡改游标或服务重启前的旧游标均无效；收到 `INVALID_CURSOR` 后点刷新。HMAC 密钥每次启动随机生成，不落盘。
- 这不是冻结快照；翻页期间的新上传可能只出现在刷新后的第一页。上一页按钮保留已访问页的游标，不生成新的服务端状态。
- 序列化**整个响应**后按 UTF-8 字节数确认不超过 16384；如必要减少行数并按最后返回行重算 nextCursor，不能先截断 JSON。统一发送层还进行第二次大小检查。
- 每连接列表突发预算 5 次、每 200ms 恢复一次（最多 5 次/秒）；超出立即 `FILE_RATE_LIMITED`，无等待队列。用户点击刷新/翻页时禁用重复查询按钮。

`DOWNLOAD_BEGIN` 使用同时匹配 fileId、owner_id、committed 的绑定查询。不存在或属于其他账户，一律 `FILE_NOT_FOUND` 和相同公开消息，不查看对方磁盘路径。附加 `userId/ownerId` 不参与授权。同一账户另一个连接可以新建自己的下载，但不能操作别的连接的 downloadId。

## 3. 控制消息与二进制头

控制消息仍是 JSON 文本 `{version:1,type,requestId,data}`。请求使用新 UUID；回复包含相同 requestId 和当前 connectionId。下载块请求的 requestId 与 downloadId 都必须是小写规范 UUIDv4。

| 请求 | data | 回复 |
| --- | --- | --- |
| `FILES_LIST` | `limit?`, `cursor?` | `FILES_LIST_RESULT`：`files`, `nextCursor`（最后一页为 null） |
| `DOWNLOAD_BEGIN` | `fileId` | `DOWNLOAD_BEGIN_RESULT`：`downloadId,fileId,name,size,sha256,committedAt,chunkBytes:8192` |
| `DOWNLOAD_CHUNK` | `downloadId,offset` | SFTD 二进制；其 requestId 对应该 JSON 请求，没有另一条 JSON 块确认 |
| `DOWNLOAD_COMPLETE` | `downloadId` | `DOWNLOAD_COMPLETE_RESULT`：`downloadId,fileId,size,sha256` |
| `DOWNLOAD_CANCEL` | `downloadId?` | `DOWNLOAD_CANCEL_RESULT`：`downloadId`；无当前下载且未指定 ID 时为 null |

`DOWNLOAD_CANCEL {}` 只清理当前连接的下载，用于 BEGIN 已发送但 ID 尚未知的情况。带 ID 必须匹配；正常取消等文件操作退出、句柄关闭后才确认。主动超时发送 `DOWNLOAD_ABORTED {downloadId,code:'DOWNLOAD_CANCELLED'}`。注销/过期使用原 `AUTH_LOGOUT_RESULT`/`AUTH_EXPIRED` 通知，断线/停服使用 WebSocket 关闭，客户端同时取消本地任务。

统一错误仍为 `{version:1,type:'ERROR',requestId,connectionId,code,message}`。文件相关代码包括 `AUTH_REQUIRED`、`INVALID_MESSAGE`、`INVALID_CURSOR`、`FILE_RATE_LIMITED`、`FILE_NOT_FOUND`、`FILE_UNAVAILABLE`、`TRANSFER_BUSY`、`TRANSFER_LIMIT`、`DOWNLOAD_NOT_FOUND`、`DOWNLOAD_OFFSET`、`DOWNLOAD_CANCELLED`。内部异常/OS 路径不通过错误消息回传。为兼容 P2，上传占满全局槽位仍返回 `UPLOAD_LIMIT`；两者使用的是同一预算。

每条二进制消息为 **92 字节头 + 1..8192 字节有效内容**，最大 8284 字节，仍小于 16 KiB。上传保持原 SFTU；下载为 SFTD：

| 偏移 | 字节数 | 字段/编码 |
| --- | --- | --- |
| 0 | 4 | ASCII magic：上传 `SFTU` / 下载 `SFTD` |
| 4 | 1 | version=1 |
| 5 | 1 | kind：上传=1，下载=2 |
| 6 | 2 | 保留字段，必须为 0 |
| 8 | 36 | requestId：含连字符的小写 UUIDv4 ASCII |
| 44 | 36 | uploadId / downloadId：同样的 UUIDv4 ASCII |
| 80 | 8 | 文件偏移，unsigned 64-bit **大端**；应用层限合法整数和文件范围 |
| 88 | 4 | 有效内容长度，unsigned 32-bit **大端**；必须与实际余下字节一致 |
| 92 | 1..8192 | 原始文件内容，没有 Base64 |

UUID 使用文本 ASCII，**不使用 `Guid.ToByteArray()`**，避免 C# 混合字节序。解码按 Latin1 保留高位再校验字符，非 ASCII 不能伪装成 UUID。固定 C#/JS 测试向量 requestId=`00112233-4455-4677-8899-aabbccddeeff`、downloadId=`ffeeddcc-bbaa-4988-8776-554433221100`、offset=`0x01020304`、payload=`a5`；首 8 字节为 `5346544401020000`，偏移80后的字节为 `000000000102030400000001a5`，自动验证完整 93 字节相等。

## 4. 下载流程、状态与资源

客户端 BEGIN 后按 offset=0 开始请求。服务器只接受当前 offset，每块处理完读取/发送后累计 sent；客户端确认 requestId、downloadId、offset 和预期块长度，**完成本地写入后**才请求下一块。重复/乱序/越界 offset 拒绝；同连接在前一块未处理完时连续发 CHUNK，会以 1008 关闭，不积累 Promise 队列。零字节文件直接走 COMPLETE，不请求或发送空数据块。

服务器每次使用异步 FileHandle.read，短读循环补足当前块，提前 EOF 失败；开始时 lstat/open/fstat 检查普通文件、链接和大小，读取前后及完成时复核大小；流式计算 SHA-256，COMPLETE 必须 sent==元数据大小且摘要相等。缺失、截断、损坏或读盘失败返回 FILE_UNAVAILABLE 并释放下载状态。即使下载失败或客户端无法收到最终确认，**绝不删除已提交源文件**。

下载状态为 `BEGIN 打开中 → 活动（逐块读取）→ 完成/取消/失效 → 关闭句柄并归还槽位`。每个任务绑定服务器 userId、connectionId、认证代次；开始、读取前后、发送前后、完成和异步返回后复核。注销、过期、断开、停服同步使 valid 失效，再等当前 IO 完成后关闭；迟到回调不能恢复任务。普通心跳、ECHO 和列表请求都不会刷新下载进度期限。

| 限制 | 当前默认值 |
| --- | --- |
| 本连接活动传输 | 上传/下载合计 1 个，互斥；清理中仍占用 |
| 全局活动传输 | 同一个 `uploadStore.active` 集合合计 4 个；不同连接可并行 |
| 单文件 / 数据总额 / 记录数 | 沿用 P2：100 MiB / 1 GiB（含上传预留）/ 1000 条；下载不重复预留存储容量 |
| 块大小 / 消息上限 | 8 KiB / 16 KiB，未放宽 |
| 发送排队 / WSS / TCP | 64 KiB / 32 / 64，未放宽；关闭压缩 |
| 下载无进展期限 / 绝对期限 | 30 秒 / 10 分钟，成功发送块才刷新无进展期限 |
| C# 待处理请求 | JSON 和二进制回复共用 8 个，超过立即拒绝；请求等待 10 秒 |
| 保活 / 停服等待 | 协议 PING 每 15 秒、PONG 等待 10 秒；沿用 5 秒有界停服 |

限额是本机课程应用的资源控制，不代表能抵御任意规模 DDoS。SQLite 事务和文件 IO 仍分开；短小同步查询不跨网络等待持有事务。P2 提交顺序和启动恢复继续验证；下载只读 committed 记录，不新增持久下载状态。异常进程退出后 OS 释放下载句柄，不进行跨目录或无归属清理。已经缺失/大小损坏的 committed 文件会使现有启动恢复检查明确失败，需人工检查存储，不伪装成下载成功。

## 5. C# 安全落盘和窗口状态

整个连接仍只有一个 ReceiveAsync 循环：先重组 WebSocket 分片并限制 16 KiB，再按 JSON 类型或 SFTD 的 requestId 分派到共享 pending 表。传输方法不自己调用 ReceiveAsync；发送仍使用同一个 SemaphoreSlim。文件打开/哈希/写入/刷盘在异步任务中执行，不在 UI 线程处理整文件，也不把整文件装入内存。

SaveFileDialog 的文件名只是建议，路径来自用户选择。网络层先拒绝已经存在的目标（即使用户在 Windows 对话框确认覆盖，也不会覆盖）。在用户选定目标的**同一目录**独占创建随机 `.sft-download-<uuid>.part`，仅此实例持有路径；写入同时计算 SHA-256。写满显示“正在校验”，要求本地大小/摘要与可信 WSS BEGIN 元数据一致，并收到 COMPLETE 确认；刷盘、关闭后调用 `File.Move(temp,target,overwrite:false)`，防止检查后目标被别人创建的覆盖竞态。完成发布后才报告“下载成功”。

取消/错误仅尝试删除本次临时文件，从不删除、截断或覆盖目标文件。会话代次在每个等待后及发布前复核；发布前在 authLock 内完成最后检查和不覆盖的改名，避免本地注销插入二者之间。已经发布的成功文件不会因随后注销而删除。磁盘不可写、目录无效、写盘异常、目标已存在均报告失败。进程被强杀/机器断电或文件系统持续拒绝删除时，可能留下随机 part 文件；首版不扫描任意用户目录自动清理，需用户确认后手动处理。

列表 UI 绑定连接对象、认证代次和列表请求序号。注销、过期、断线或重新认证时清空列表/游标；旧请求即使晚到也不能更新新身份的列表。不同 UI 操作可共享连接查询身份，但同连接上传/下载按钮互斥。取消下载后可继续 ME、列表或上传；正常完成后不必重连。

API 依据：[Node 22.16 FileHandle 异步读取](https://nodejs.org/download/release/v22.16.0/docs/api/fs.html)、[.NET File.Move 的 overwrite 参数](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.move?view=net-10.0)、[ClientWebSocket 单并发接收约束](https://learn.microsoft.com/en-us/dotnet/api/system.net.websockets.clientwebsocket.receiveasync?view=net-10.0)。
