源码检查发现网络文件操作本来就在 Task.Run 中，但 Form 为每个 8 KiB 分块使用 `Progress<T>` 向 UI 同步上下文排队，64 MiB 会排入约 8192 次进度/自动布局更新。结合界面消息延迟，判断该队列洪泛是主要原因，待 GUI 复测确认修复有效。上传和下载均改用 `UiTransferProgress<T>`：工作线程只保留最新进度，WinForms Timer 每 100ms 最多渲染一次；Dispose 停止计时并清空待处理值。原有身份代次、任务代次和最终结果检查保留。网络协议、分块、文件哈希和服务端未修改。

修复前两个 Form 源文件及哈希保存在 `before-progress-fix/`。两个旧客户端经 Alt+F4 正常关闭，dotnet run 均退出 0；这是空闲关窗，不冒充 F05 传输中关窗。修复后构建在 `artifacts/validation/2026-11-24T09-36-32-133Z-build/`，退出 0、0 警告、0 错误。两个修复版窗口由用户登录，B04 已复测；旧的通过项属于修复前版本，受影响的取消/身份切换项继续验证。
