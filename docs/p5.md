## 3. 从ZIP起点的执行及发现

三个目录均为项目外全新空目录，源码逐项从ZIP的SOURCE-MANIFEST读取并核对，不从原工程复制源码或构建产物。每个副本都有独立npm缓存、NuGet包目录、DOTNET_CLI_HOME、TEMP/TMP；Node测试创建随机回环端口和临时账户。所有测试服务关闭后清理本轮数据，源码、依赖/构建产物及日志保留供核查。

1. **运行时选择缺陷**：原C#证书负例夹具`ProcessStartInfo("node")`可能通过PATH启动旧Node。现在协调脚本传入process.execPath，C#明确使用它；run-node.mjs给本次子进程设置PATH、固定版本/路径及NODE_OPTIONS运行时断言，C#再派生的Node同样受校验。运行时审计不包含参数或密码。
2. **首次构建不足**：旧validate.mjs使用--no-restore，不适合裸源码包。移除该开关，实际四项目还原并构建；记录真实运行时、日志采用UTF-8流解码并等待close收全输出。
3. **执行环境限制**：初版PS启动器在获准的复现环境可运行，但普通受管终端明确报“running scripts is disabled”。没有改执行策略、没有用Bypass；改为便携node.exe直接执行JavaScript启动器，普通受管终端info实际通过。旧PS启动器不进入当前源码。
4. **中文路径暴露的C#检查工具编码缺陷**：RC1/RC2后端均34/34，但C#在读取含中文TEMP路径的UTF-8 stdin JSON时按Windows代码页解析失败（JsonException，协调进程退出1）。修复Console.InputEncoding/OutputEncoding为UTF-8，未改Networking业务逻辑、证书验证或协议。RC3从新ZIP重新还原、构建，实际C#全部通过。
5. **汇总工具编码缺陷**：RC3各实际命令均退出0，最后Python默认GBK读取UTF-8 runtime.jsonl报UnicodeDecodeError，汇总进程退出1。已修正明确encoding='utf-8'，并用--verify-existing重新核对既有命令退出码、日志哈希、全部运行时及源码/锁哈希，退出0。该步骤是证据复核，**不是重新执行测试**。

所有修复先同步原工程，再打包新RC；副本源码没有就地打补丁来掩盖归档问题。没有发现业务源码或锁文件遗漏。RC2与RC3的全部server-node以及实际WinForms/Networking源码逐字节相同；RC3只改检查项目编码和复现工具。因此最终采用RC2完整后端回归 + RC3受影响的完整构建/安全/C#复测，没有为凑次数再跑同一后端整套。



start/health默认127.0.0.1:8443；启动器及服务器打印版本和可执行路径。原证书和账户继续使用，不重建。新副本首次使用npm-ci/certs动作；certs仍默认不覆盖已有证书。端口若被占用，只报告、不杀其他进程。当前停止流程仍由服务器处理Ctrl+C；P5测试通过service.stop和停服夹具验证有界释放，**新启动器的实际控制台Ctrl+C交互未另行验收**。

可重复准备与独立复现（新目录不得已存在）：


完整默认流程为info/npm-ci/build/certs/smoke/backend/csharp。--checks用于明确记录有理由的局部复测，不得用它跳过失败项冒充完整通过。--verify-existing只检查已完成证据；不能在失败命令仍存在时宣称通过。普通受管环境的Git/用户目录/CIM访问限制仍可能存在；不通过修改全局权限或执行策略绕过。
