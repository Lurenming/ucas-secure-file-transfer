## 4. 开发证书与信任来源

在 `server-node` 中运行：

```powershell
npm.cmd run certs:dev
```

该命令使用已有 OpenSSL，通过 RSA 3072 位密钥和 SHA-256 签名生成证书。CA 有效期 365 天，服务器证书有效期 90 天。服务器证书明确包含 `DNS:localhost`、`IP:127.0.0.1` 的 SAN、`CA:FALSE`、`digitalSignature/keyEncipherment` 及 `serverAuth` EKU。

| 本机文件 | 用途 | 能否给客户端 |
| --- | --- | --- |
| `server-node/certs/public/dev-ca.crt` | CA 公共证书，作为应用内信任根 | 可以，只从可信本机目录取得并核对 |
| `server-node/certs/public/server.crt` | HTTPS/WSS 服务器公共证书 | 客户端会在 TLS 握手时收到；不是 CA 选择项 |
| `server-node/certs/private/server.key` | 服务器私钥，仅 Node 服务读取 | 不可以 |
| `server-node/certs/private/ca.key` | CA 签发私钥，日常服务不读取 | 不可以 |

公共证书和私钥目录分开。Windows 下生成器将 `private` 目录的继承权限移除，仅授予当前 Windows 用户完全控制；实际检查已确认该 ACL。以生成证书的同一用户运行后端。所有生成证书和私钥均被 Git 忽略，不作为客户端资源或日志内容保存。

生成器采用临时目录，成功后才发布完整 `certs` 目录。已有完整文件时直接保留；目录不完整时明确失败，不尝试补写或覆盖。重复执行后，四个文件的 SHA-256 内容哈希均保持不变。不会自动向 Windows 全局或当前用户根证书库导入任何证书。

本次 CA 的公共指纹（SHA-256）：

```text
4E:F2:22:B7:22:B3:B1:35:13:AD:82:BC:8F:E0:51:EF:98:BE:C3:D7:42:17:42:FA:E8:EA:29:77:59:32:39:3F
```

可在可信本机目录核对：

```powershell
openssl x509 -in .\certs\public\dev-ca.crt -noout -fingerprint -sha256
```

重新生成另一组证书时指纹会改变，客户端需要重新核对并选择新 CA。不要从不可信网页、聊天附件或服务器临时返回的内容中自动建立信任。当前窗体只会查找工作区中的默认公共 CA 路径，或使用用户明确选择的本机文件；不会通过网络下载 CA。

**吊销限制：** 本地开发 CA 没有 CRL/OCSP 服务。C# 使用 `RevocationMode.NoCheck`，只省略吊销查询；链、有效期、服务器用途和 SAN 主机名仍必须通过。证书不能被在线吊销；私钥泄漏或需要撤销信任时，应停止使用该 CA 并人工轮换、重新分发可信公共 CA。本方案是课程本机开发信任，不等价于完整生产 PKI。

## 6. 最小消息协议与边界

全部应用消息为 UTF-8 JSON 文本。建立连接后服务器立即发送：

```json
{"version":1,"type":"HELLO","connectionId":"服务器生成的 UUID"}
```

客户端每次生成新的 UUID `requestId`：

```json
{"version":1,"type":"ECHO","requestId":"客户端生成的 UUID","data":{"text":"测试文本"}}
```

服务器回复：

```json
{"version":1,"type":"ECHO_RESULT","requestId":"相同的 UUID","data":{"text":"相同文本"},"connectionId":"本连接的 UUID"}
```

一次连接可以反复请求。`requestId` 用来匹配哪一次请求，`connectionId` 标识哪一条连接；重连会得到新 connectionId。文本长度上限为 1024 个 UTF-16 代码单元，与 JavaScript `string.length` 和 C# `string.Length` 一致。

| 约束或错误 | 行为 |
| --- | --- |
| 非法 JSON | 返回 `version:1,type:ERROR,code:INVALID_JSON,connectionId`，连接可继续使用 |
| 错误字段类型/版本、未知类型、非 UUID requestId、文本超限 | 返回 `ERROR/INVALID_MESSAGE`；合法 requestId 可回显 |
| WebSocket 二进制消息 | 关闭码 1003 |
| 单条完整消息超过 16 KiB，含累计分段 | 关闭码 1009，由 ws 校验 |
| 最大 WSS 连接数 | 32；超限升级请求返回 HTTP 503 |
| 总 TCP/TLS 连接数 | 上限 64，限制升级前连接占用 |
| 每连接待发送字节 | 64 KiB；后端超限关闭码 1013 |
| 消息压缩 | 服务端关闭；C# 不配置压缩 |
| 非 `/ws` 升级请求 | HTTP 404 |
| 带 Origin 的浏览器升级请求 | HTTP 403，本阶段只支持原生客户端 |

后端不把非法 JSON/字段错误抛到进程顶层；协议级错误仅关闭相应连接。每个连接自己的心跳、超时和状态在 close 时清理。C# 同样限制完整接收消息为 16 KiB，严格解码 UTF-8，并校验 HELLO、版本、connectionId、requestId 和回显文本。

## 7. 保活、异步接收和关闭

**协议级保活：** 后端每 15 秒发带随机标识的 WebSocket PING，等待匹配 PONG 最多 10 秒；未回应则终止该连接。正常空闲不需要应用 ECHO。C# 明确设置 `KeepAliveInterval = 15 秒`、`KeepAliveTimeout = 10 秒`，并一直运行 ReceiveAsync 循环，让 .NET 处理协议控制帧。ECHO 是应用层请求，不作为 PONG 的替代。

**后端关闭：** Ctrl+C 设置停止状态并关闭监听，向已有 WSS 连接发送 1001；最多等待 5 秒，再 terminate 残留 WSS、销毁本服务的 TCP/TLS socket。连接关闭事件清除心跳及关闭定时器。不会扫描或结束其他程序。

**C# 连接：** 一次连接一个 `SecureConnection` 对象；一个持续的异步接收循环汇总消息片段，`SemaphoreSlim` 串行化发送和关闭帧，最多保留 8 个待完成 ECHO 请求以及 64 KiB 发送预算。连接/HELLO 与 ECHO 分别有 10 秒期限。断开时先发关闭帧并等待接收循环结束，两个等待阶段各不超过 5 秒；超时取消并 Abort，随后释放 socket、CA 对象及取消源。

**窗体：** 网络调用使用 async/await，不同步等待网络。每次连接拥有独立对象和 generation 编号，日志及状态回调在 UI 线程执行前检查两者；旧连接的排队回调不能修改新连接的状态。断开、失败和关闭窗口走统一清理路径，日志长度也有上限。

## 9. WinForms 人工验收步骤

1. 按第 5 节启动后端和客户端，核对默认地址 `wss://127.0.0.1:8443/ws`。通过“选择 CA”选取可信目录的 `server-node\certs\public\dev-ca.crt`，核对公共指纹。
2. 点击“连接”。预期显示“已连接”，日志出现 connectionId；窗口可以拖动、输入，不应冻结。
3. 连续发送不同文本和中文。每次 requestId 不同，connectionId 相同，返回文本一致；无需每次重新连接。
4. 不发送应用消息等待至少 60 秒，再发送，确认 connectionId 不变。
5. 点击“断开”，确认状态、按钮恢复；再连接，确认新 connectionId，旧日志回调不把状态改回旧连接。
6. 再开一个客户端窗口，两边分别发送不同文本，确认互不串消息。
7. 后端按 Ctrl+C。确认两边显示断开、发送不可用，窗口仍响应；重启后端后能够再次连接。
8. 分别在空闲、连接中、发送中关闭窗口，确认客户端进程最终退出，无未处理异常。使用不存在的 CA、另一测试 CA 或 `ws://` 地址连接应失败，且可以改正后重试。
9. 检查缩放、调整窗口尺寸时的控件和日志显示。关闭客户端与测试后端，确认 8443 已释放。

以上列表供用户执行；在没有实际操作结果前仍记为未验证。

## 10. 关键 API 的理解与参考

`https.createServer` 创建唯一的 TLS 监听器，Express 处理普通 HTTP 请求，ws 只处理其中 `/ws` 的升级请求。`maxPayload` 限制完整 WebSocket 消息，`bufferedAmount` 用于限制待发送积压，PING/PONG 是 WebSocket 控制帧而不是 JSON 消息。[ws 官方 API](https://github.com/websockets/ws/blob/master/doc/ws.md)

C# 自定义校验并非看到“系统不信任”就放行：它先检查证书是否存在、有效期、SAN 主机名和 serverAuth，再用 `CustomRootTrust` 与所选公共 CA 重建链，保留 `NoFlag` 验证规则。主机名校验关闭通配符和 Common Name 回退，要求 SAN 精确匹配。[CustomTrustStore](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.x509chainpolicy.customtruststore?view=net-10.0)、[MatchesHostname](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.x509certificate2.matcheshostname?view=net-10.0)

`KeepAliveTimeout` 配合正的 `KeepAliveInterval`，使 ClientWebSocket 使用需回应的 PING/PONG；持续接收循环不可省略。[Microsoft KeepAliveTimeout 文档](https://learn.microsoft.com/en-us/dotnet/api/system.net.websockets.clientwebsocketoptions.keepalivetimeout?view=net-10.0)

证书扩展使用 OpenSSL 的标准 `basicConstraints`、`keyUsage`、`extendedKeyUsage`、`subjectAltName`，没有自己实现密码算法。[OpenSSL 扩展配置](https://docs.openssl.org/3.0/man5/x509v3_config/)
