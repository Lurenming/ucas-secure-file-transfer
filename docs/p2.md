## 3. 控制消息与完整流程

控制消息仍为 JSON 文本：`version:1, type, requestId(UUID), data(对象)`。回复保留相同 requestId 和服务器 connectionId。身份取服务器连接绑定，不读取客户端 owner/userId 来授权。

| 请求 | data | 成功响应及 data |
| --- | --- | --- |
| `UPLOAD_BEGIN` | `name`: 显示文件名；`size`: 非负安全整数，字节数 | `UPLOAD_BEGIN_RESULT`: `uploadId`、`chunkBytes:8192` |
| 二进制上传块 | 见下一节，含独立 requestId | JSON `UPLOAD_CHUNK_RESULT`: `uploadId`、`received`（累计写入字节数） |
| `UPLOAD_COMPLETE` | `uploadId`、`sha256`（64 位小写十六进制） | `UPLOAD_COMPLETE_RESULT`: `fileId`、`name`、`size`、`sha256` |
| `UPLOAD_CANCEL` | 通常含 `uploadId`；也可 `{}` | `UPLOAD_CANCEL_RESULT`: `uploadId`，无当前上传时为 null |

`UPLOAD_CANCEL {}` 只取消当前连接自己的上传，供 BEGIN 已发出但客户端尚未取得 uploadId 时清理使用。带 id 的取消必须匹配当前连接；不能取消其他连接/其他用户。已提交的文件不能取消，返回 `UPLOAD_ALREADY_COMMITTED`。正常取消等待当前磁盘操作退出并清理未完成数据后才确认。

流程：登录 → BEGIN → 等待 uploadId → 发送第一个二进制块 → 等待该块 ACK → 发送下一块 → 全部字节 ACK 后显示“正在校验” → COMPLETE（客户端摘要） → 服务器校验长度/摘要、写盘并提交元数据 → 最终成功确认。

零字节文件走 BEGIN → COMPLETE，SHA-256 为标准空内容摘要，不发送空数据块。ECHO、ME、协议 PING/PONG 不被上传占用，也不刷新上传空闲期限。

服务器超时会发无 requestId 的 `UPLOAD_ABORTED`，data 含 uploadId/code；注销/认证过期沿用 P1 身份事件。错误仍为 `ERROR`，常见代码：`AUTH_REQUIRED`、`INVALID_MESSAGE`、`UPLOAD_NOT_FOUND`、`UPLOAD_BUSY`、`UPLOAD_SIZE`、`UPLOAD_OFFSET`、`UPLOAD_HASH`、`UPLOAD_LIMIT`、`UPLOAD_QUOTA`、`UPLOAD_CANCELLED`、`UPLOAD_STORAGE_ERROR`、`UPLOAD_ALREADY_COMMITTED`。不会返回磁盘路径、SQL 异常细节或认证秘密。

## 4. 二进制头：固定 92 字节

一个完整 WebSocket 二进制消息承载一个块，可由多个 WebSocket 分片组成；ws 先汇总，再执行下列检查。总长为 **92 + 有效数据长度**，最多 8284 字节，小于现有 16 KiB 限制。

| 起始偏移 | 字节数 | 字段 | 编码/值 |
| --- | --- | --- | --- |
| 0 | 4 | magic | ASCII `SFTU`，hex `53 46 54 55` |
| 4 | 1 | version | `01` |
| 5 | 1 | kind | `01`：上传数据块 |
| 6 | 2 | reserved | 必须为 `00 00` |
| 8 | 36 | requestId | 小写、带连字符的 UUID v4，36 个 ASCII 字节 |
| 44 | 36 | uploadId | 同上，取服务器 BEGIN 返回值 |
| 80 | 8 | offset | 无符号 64 位，**大端序**；此块第一个数据字节的文件偏移 |
| 88 | 4 | dataLength | 无符号 32 位，**大端序**；1–8192 |
| 92 | dataLength | 文件内容 | 原始字节，不是 Base64 |

头中 UUID 是 `Guid.ToString("D")` 的 ASCII 文本，**不使用 `Guid.ToByteArray()`**，因此不存在 C# 混合字节序与 JS UUID 的差异。JS 使用 latin1 保留标识字段字节的高位再做 ASCII 格式校验，不让高位字节被掩掉后伪装成合法字符。偏移先检查不超过 JS 安全整数，再与当前已收偏移严格相等比较。

一致性测试向量：requestId=`00112233-4455-4677-8899-aabbccddeeff`，uploadId=`ffeeddcc-bbaa-4988-8776-554433221100`，offset=`0x01020304`，数据=`a5`。头首 8 字节为 `5346545501010000`，偏移和长度字段为 `000000000102030400000001`。C#/JS 实际生成的完整 93 字节已逐字节比较。

每块单独生成 requestId；JSON ACK 用该 requestId 匹配请求，再检查 uploadId 及累计 received。客户端等待 ACK 才发送下一块。服务器处理 FileHandle.write 的短写，循环到本块全部写完；客户端按 ReadAsync 实际返回的字节数发送，不能假定一次读满缓冲。

无上传/错误归属的合法头返回错误；错误头、截断、不合法标识、零长度块、长度字段与消息不一致等关闭 1003。完整消息超过 16 KiB 仍关闭 1009。偏移重复/乱序、越过声明大小均拒绝。尚未完成上一块写入就连续发送下一块时，关闭 1008 并取消该上传，**不积累 Promise 队列**。P0.2 的“所有二进制都拒绝”已改为“允许合法上传块，继续拒绝无对应上传或畸形块”；服务器到客户端仍只发送 JSON，C# 接收端继续拒绝未经定义的二进制回复。

## 5. 身份、名称与资源限制

每个上传保存服务器确定的 owner_id、connection_id、auth_generation。BEGIN、每块写入前后、COMPLETE 的每个异步阶段结束后都复核：连接仍开放、身份有效、userId 与认证代次一致、上传尚未取消。注销/过期/断开先同步失效，再等待已提交到内核的异步操作结束后清理；迟到操作不能重新生效。

显示名称只作为 SQL 元数据，绝不参与存储路径。规则：非空、最多 120 个 UTF-16 代码单元且最多 240 个 UTF-8 字节、必须为有效 Unicode；拒绝斜线/反斜线、冒号、控制字符、Windows 非法字符、末尾点/空格和设备保留名。普通中文名称可用。同名上传生成不同 UUID 文件标识，互不覆盖。

| 限制 | 默认值 |
| --- | --- |
| 单文件 | 100 MiB（104857600 字节） |
| 每连接活动上传 | 1 |
| 全局活动上传 | 4，各自异步，不全局串行 |
| 总存储配额 | 1 GiB：已提交大小 + 所有在途声明大小预留 |
| 文件记录数 | 1000（包括在途），避免零字节文件无限增长 |
| 上传空闲期限 | 30 秒；只由有效上传进展刷新 |
| 上传绝对期限 | 10 分钟，不续期；认证 15 分钟期限仍独立生效 |
| 接收积压 | 每连接最多一个磁盘操作，没有等待块队列 |
| 原 WSS 约束 | 16 KiB 消息、64 KiB 发送队列、32 WSS / 64 TCP 连接，压缩关闭 |
| 关闭等待 | 5 秒；残留 socket 强制清理，未完成磁盘清理超时则入口退出 1，交给下次启动恢复 |

预留记录和内存计数在第一次异步 open 之前完成，多个 BEGIN 不会同时穿透配额。只有未完成文件确已删除后才释放预留；清理失败保留记录/预留并拒绝新增上传，避免反复失败绕过配额。已提交文件始终计入配额。

这些是本机课程软件的应用层限额，**不代表能抵御任意规模 DDoS**。没有实现公网带宽治理、每用户公平调度、完整生产审计或恶意内容扫描。

## 6. 私有存储、提交与恢复

默认布局：

```text
server-node/data/
  accounts.sqlite               # P1 账户，保持原有内容
  uploads/
    .sft-uploads                # 应用目录标记
    writer.lock                 # 本应用写入进程 PID
    uploads.sqlite             # 文件元数据，伴随 WAL/SHM
    objects/
      <服务器 UUID>.part       # 临时文件
      <服务器 UUID>.bin        # 已发布文件
```

`SFT_DATA_DIR` 仍可指定专用数据根，上传目录位于其 uploads 子目录。已有非空目录没有本应用标记时拒绝接管。路径标识来自服务器 UUID，不跟随对象/数据库路径符号链接。原始内容不通过 Express 静态目录公开，不执行、不解压。

Windows 上传目录/objects 的 DACL 设置并读取验证为当前 Windows SID 一条 FullControl 规则、禁用继承，并对子项继承；只修改这两个应用专用目录。已有正确 ACL 直接复用，避免无谓重设。实际检查已有 `server-node/data` 的 ACL 为受保护、1 条规则、0 条继承规则，未修改其内容；这只是本轮只读观察，**不回填为 P1 人工文件权限验收**。隔离测试实际运行了上传目录 ACL 设置/读回和恢复复用；未用另一个 Windows 用户执行访问拒绝测试。POSIX 使用目录 0700、文件 0600。

writer.lock 通过独占创建获取。发现其 PID 活跃或无法确定时拒绝启动第二个写入者；仅清除已确认不存在进程的、本应用标记目录内的陈旧锁。PID 重用时宁可拒绝并提示人工检查，不能删除运行中服务的状态。

`files` STRICT 表：`file_id` 主键，`owner_id`、`connection_id`、`auth_generation`、`display_name`、`size`、`sha256`、`state`、`created_at`、`committed_at`。状态为 receiving → committing → committed。所有外部输入均通过 SQL 参数绑定；取消后的未完成记录在文件清理成功后删除，不保留无限增长的取消历史。

提交顺序：

1. 同步插入 receiving 记录并计入完整声明大小预留；随后用 `wx` 独占创建 part。碰撞或已有文件时不覆盖。
2. 逐块异步写盘、增量 SHA-256，写完本块后才 ACK。收到 COMPLETE 时检查实际接收数等于声明大小、两个摘要一致。
3. `FileHandle.sync()` 刷新文件，关闭句柄；复核身份/代次。将记录更新为 committing，并保存摘要。
4. 同目录使用 `fs.link(part, bin)` 独占创建最终名称，不使用可能覆盖目标的 rename。NTFS 硬链接共用同一内容，不复制第二份文件；不支持硬链接的文件系统会明确失败，不静默降级。
5. 再次复核状态，SQLite 更新为 committed（WAL、synchronous=FULL）。最后一次检查与该决定之间没有异步等待。这是提交点。
6. 删除 part 链接，再发最终 ACK。若删临时链接失败，保留 committed 记录，由启动恢复清理临时链接。**此后 ACK 发送失败、断线、注销或取消均不能删除已提交内容。**

文件系统与 SQLite 并非同一个原子事务。启动时在监听前检查有记录的对象：receiving/committing 统一清理、不续传；若存在 bin，须通过文件 dev/ino 确认它与 part 是同一内容的链接才能删除。committed 保留 bin，只清理能够确认归属的 part。丢失/大小异常的已提交文件、无法证明归属的路径等使启动失败，留待人工检查。**不递归扫描或删除未记录文件**，测试中的无关文件保留。

此顺序已验证进程中断恢复，不保证突然断电、损坏磁盘/文件系统、手工篡改元数据后的自动恢复。目录项持久性仍受 OS/文件系统影响；已提交对象异常时不会假装恢复成功。

API 依据：[Node 文件 API](https://nodejs.org/download/release/v22.16.0/docs/api/fs.html) 中的异步写入、sync、link 和独占打开；没有自行实现文件系统事务或密码算法。

## 7. C# 与窗口行为

上传网络类是 SecureConnection 的 partial 文件，仍由 ConnectionChecks 编译同一份源码。读取/哈希放在后台任务，FileStream 使用异步读取，固定 8 KiB 缓冲、增量 SHA-256，不把整个文件加载到内存。所有 WebSocket 发送继续使用同一 SemaphoreSlim，接收循环持续运行并按 requestId 分派 ACK。

源文件从开始到最终确认一直以 `FileShare.Read` 打开：在本机 Windows 上拒绝写入/删除共享冲突，已有写入句柄时上传失败；完成前还检查长度、最后修改时间和额外 EOF。检测到变化会取消。不能保证对不遵守 Windows 文件共享语义的远端文件系统或特权写入提供同等防护。实际验证了已有写入句柄的拒绝。参考：[FileStream 构造与共享参数](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.-ctor?view=net-10.0)。

进度依据服务器 received，100% 字节确认不代表成功，随后显示“正在校验”。仅最终确认字段/摘要/大小匹配后显示成功，并展示 fileId、字节数和 SHA-256。旧连接或上一上传的进度回调不能污染新状态。

用户取消在文件读或两次请求之间处理；不在一次 WebSocket send 中途强行取消。会等待当前块 ACK（原请求期限 10 秒），再发送 CANCEL 并等待清理结果。正常取消保留身份/连接；取消清理结果不确定时断开以失效上传。COMPLETE 一旦发送，提交可能先于取消发生：客户端等待最终结果，若已提交则报告成功，不能承诺撤销。

最终 ACK 因断线/超时未收到时，抛出 `UploadOutcomeUnknownException`，提示 uploadId 和“请人工核对，不要自动重传”。服务器可能已经 committed；本轮没有重传、提交状态查询 API或删除接口。操作者可在可信本机用 SQLite 只读工具按 file_id 核对 `uploads.sqlite`，不能仅凭客户端报错断言文件没存下。
